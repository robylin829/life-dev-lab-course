# Task 8：交付作品與開發證據

[線上互動版](https://life-development-lab.vercel.app/#/tasks/8) · [任務目錄](README.md)

## 任務目標

展示真正上線、可登入與保存個人資料的作品，附程式庫與驗收證據。

- 操作時間：約 45 分鐘
- 開始前：完成 Task 7。老師或同學能開啟正式網址。

## 先理解：完成的定義

首頁能開只是第一步。真正全端作品要完成 UI → 登入 → API → 資料庫 → 重新讀回的使用流程，並說明資料權限。

## 步驟 1：決定這次要解決誰的問題

以「忙碌學生安排報告與社團」為起點，選三項核心功能：登入、個人行程、完成狀態。用下方成果工作台寫出自己的問題與成果，不一次追加整個社群平台。

**預期結果**

一句話能說清楚對象、痛點與使用情境。

<details>
<summary>卡住了？查看排錯提示</summary>

時間不夠時縮減功能數，保留登入、資料隔離與完整流程。

</details>

## 步驟 2：依驗收表交換測試

請同學開正式網址。測新增有效行程、空白名稱、時間相同、編輯、完成、重整、登出、另一帳號登入。執行 pnpm test:cloud 驗證實際 RLS；記錄測試版本。

**預期結果**

每項都有預期／實際／結果；失敗項目有修復或明確已知限制。

<details>
<summary>卡住了？查看排錯提示</summary>

只有截圖不能驗證權限；SQL Editor 的管理員結果也不能代表使用者身分。

</details>

## 步驟 3：整理版本與 AI 協作證據

將需求、一次 AI 修改、你指出的錯誤、修正差異與檢查結果整理到 README 或 PR。下方工作台可下載 Markdown 展示稿，再放進自己的 repo。

**預期結果**

能從一個 commit 或 PR 追到已發布的功能。

<details>
<summary>卡住了？查看排錯提示</summary>

不要把 token、測試帳密或完整 .env 放進報告。用變數名稱與設定位置說明即可。

</details>

## 步驟 4：進行三分鐘 Demo

0:00–0:30 說使用者與問題；0:30–1:30 示範登入、新增、重整；1:30–2:30 說明一次錯誤與驗證；2:30–3:00 說限制與下一步。老師追問時，打開程式差異或權限演練輔助解釋。

**預期結果**

能用自己的話說明資料怎麼流動、AI 幫了什麼、自己做了什麼判斷。

<details>
<summary>卡住了？查看排錯提示</summary>

網路不穩時使用事先錄下的操作證據與列印教案，清楚說明這次不是即時雲端操作。

</details>

## 驗收與提交

- [ ] 作品、repo 與驗收證據可交給別人重現
- [ ] 三分鐘展示包含一次錯誤、修正與未完成事項

在 [操作證據](../worksheets/evidence.md) 記下：貼上作品與 repo 連結、三分鐘展示大綱、一次 AI 協作與驗證故事。

此清單是自評，不代表教師網站已連線驗證你的專案。

## 觀念檢核

哪一份交付最能支持「作品完成」的判斷？

1. 只有首頁截圖
2. 只有 AI 說完成的聊天記錄
3. 正式網址、repo、驗收結果與已知限制

<details>
<summary>作答後查看解析</summary>

答案：3。可追溯的版本與可重現的流程，才能讓他人檢查作品。

</details>

## 進階挑戰

邀一位未參與開發的同學依 README 啟動作品，記錄他卡住的位置。
